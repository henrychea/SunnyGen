# Today inbox, Home renamed to Images, and the shoot planner

- Date: 2026-11-24
- Status: open, PR #23

## Summary

Home is now Today: one screen that answers what is running, what finished and has not
been looked at, what failed, and how much ran this week. The image wall that used to own
`/` moved to `/images` with its composer, and the sidebar gained an Images entry plus a
Shoots entry. The shoot planner at `/shoots` turns one avatar, some wardrobe pieces,
scenes and poses into up to eight looks in one folder, each with an editable prompt and
its reference thumbnails, then queues them and shows the results live.

## Why

Opening SunnyGen meant landing on the image wall and re-reading it to find out what had
happened. Running jobs, unreviewed renders and failures were spread across Images, Video,
Studio and Gallery, so the first minute of every session was spent looking for them. The
same wall also meant `/` had no room for anything but images.

A shoot was the other repetitive job: the Studio look builder shoots one look at a time,
so eight wardrobe and scene variations meant eight manual runs, eight prompts, and eight
folders. Nothing counted the combinations or kept the prompt and reference order in sync
with the look builder.

## What changed

- `apps/web/src/routes/index.tsx` moved to `apps/web/src/routes/images.tsx`, and its route
  id is `/images`. The page body is unchanged apart from the title and the wall grouping
  now coming from `buildWallEntries` in `apps/web/src/lib/wall-groups.ts`, the helper the
  Studio branch extracted. Query keys stay as they were.
- `apps/web/src/components/sidebar.tsx`: Today at `/` (Sparkles), Images at `/images`
  (image icon), and Shoots at `/shoots` (camera) after Studio. Mobile nav uses the same
  list. `apps/web/src/routes/studio.tsx` sends a trained avatar to `/images`.
- `apps/web/src/routes/index.tsx`: the new Today page. Sections are Running now (queued and
  running generations across Images, Video and Studio as `JobCard`s, polling every 3s while
  anything is in flight), New results to review (finished generations with no
  `params.reviewedAt`, newest first, as `OutputCard`s that open the existing `WallModal`,
  with Keep, Star, Delete and Move to folder per card plus Keep all), Needs attention
  (failed generations with the shared Retry and a Dismiss that deletes the record, plus
  `CleanupFailedButton`), This week, and a quick actions row for Images, Video, Studio and
  New shoot. Every section has an empty state and every action toasts.
- `apps/web/src/server/dashboard.functions.ts`: `loadToday` returns running, unreviewed,
  failed and this week's per provider and model counts; `setGenerationReview` writes
  `params.reviewedAt` and `params.starred` onto the generation's params JSON. No migration.
- `apps/web/src/components/failure-actions.tsx` takes an optional `onRetried`, and
  `apps/web/src/components/home/wall-cards.tsx` passes it through `JobCard`, so a retry
  started on Today can report back without a second set of buttons.
- `apps/web/src/lib/studio-shot.ts`: one pure helper builds a looked shot's prompt and
  reference order (avatar crops first, one garment view, pose, scene). It now backs both
  `apps/web/src/components/studio/look-builder.tsx` (`promptFor`, the reference list and
  the prompt preview all call it) and the shoot planner, so the two cannot drift.
- `apps/web/src/lib/shoot-plan.ts`: `shootCombinations` enumerates avatar x garment x scene
  x pose with garments outermost and poses innermost, skips an empty scene or pose step,
  caps at the limit and reports how many were dropped. Covered by
  `apps/web/src/lib/shoot-plan.test.ts` (count, order, cap, skipped steps, missing avatar).
- `apps/web/src/routes/shoots.tsx`: five steps (avatar, wardrobe, scenes, poses,
  combinations). The combination grid shows each cell's prompt in an editable textarea,
  the ordered reference thumbnails, a checkbox to drop the cell, and the global model,
  ratio and quality pickers reused from the Images composer. The cap is `MAX_BATCH` from
  `apps/web/src/components/home/composer.tsx` (exported for this) and is stated on screen.
  Queueing creates one folder named `Shoot <avatar> <date>`, submits each kept cell with
  `params.origin: 'shoot'` and that folder, then shows queued and finished looks live from
  the wall, and the same looks appear in Today.
- `apps/web/src/routeTree.gen.ts` regenerated by the Vite plugin for `/images` and
  `/shoots`.

## How to verify

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm format:check
```

By hand, against a throwaway copy of the demo database:

```sh
cp -r <demo-data-dir> /tmp/sunnygen-today
SUNNYGEN_DATA_DIR=/tmp/sunnygen-today PORT=8982 NITRO_PORT=8982 \
  pnpm --filter @sunnygen/web dev
```

Open `/`. Running jobs poll every 3 seconds, Keep removes a card from the review pile, Star
survives a reload, Delete and Move to folder update the pile, Keep all empties it, and a
failed card shows Retry and Dismiss. Open `/images`: the wall, composer and the `?avatar=`
deep link still work, and links that used to point at the generator now point at
`/images`. Open `/shoots`: pick an avatar, two garments, a scene and a pose, check that the
combination count and the cap notice are right, edit a prompt, then queue (needs a provider
key).

## Limits

- No real provider call was made. The UI check ran on a throwaway demo database seeded with
  running, finished, failed and shoot generations, so queueing a real shoot and watching a
  provider finish it was not exercised end to end.
- Spend is counts, not money. Nothing records what a run costs (catalog prices are display
  strings like "$0.045 to $0.15 per image"), so the week section counts finished runs per
  provider and model and says so in the UI.
- Reviews live in the generation's params JSON. That keeps the schema untouched but means
  reviewed and starred cannot be queried or indexed, and they travel with a retry's copied
  params.
- The review pile shows every finished generation `loadGenerationWall` returns, capped at
  its 80 finished rows, with no paging or filtering beyond the existing wall limits.
- Shoot combinations are capped at `MAX_BATCH` (8). Above that the first eight are shown and
  the notice asks to trim the picks; the planner does not page through the rest.
- The shoot setup is not saved. Reloading the planner clears the picks; only the queued
  folder and its generations persist.
- The shoot queue shows recent generations with `params.origin === 'shoot'`, so older
  shoots are only in Gallery.
- Today's poll runs only while something is queued or running; a page left open overnight
  shows stale timestamps until it is reloaded.
