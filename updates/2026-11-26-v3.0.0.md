# SunnyGen 3.0.0

- Version: 3.0.0
- Date: 2026-11-26
- Status: release branch `henrychea/release-3.0.0`, not merged

## Summary

3.0.0 is three features and one audit. The app gets a dark theme, an NSFW mode that switches
provider safety fields through the provider schema and unlocks two uncensored providers, and a
video copy pipeline that turns a reference clip into a shot list and a joined remake. The audit
pass lands with them, so both themes and the new surfaces ship at the same contrast, tap-target
and copy standard as the rest of the app.

Everything below links the document that shipped with its work. Those hold the why, the file
list, the verification steps and the remaining limits; this page is the release-level view.

## Dark theme

Settings → Theme offers System, Light and Dark. The choice is one `localStorage` key
(`sunnygen.theme`) and applies per device, because the phone and the desktop do not share an
appearance setting worth guessing about. A pre-paint script sets `html[data-theme]` before the
first frame, so a dark device never flashes the light palette, and the meta `theme-color`
follows so the browser chrome matches. Every colour stays on the existing token layer: dark is a
second `@theme` block, not `dark:` variants scattered through components.

## Antislop audit

Twenty findings across the two themes and the shared UI, all fixed: six muted text tiers below
the contrast floor collapsed to one `text-ink/65` floor, container borders moved to a real
`--color-line-strong` value, the light warning token was darkened to pass AA, card shadows and
the list entrance animation are gone, `backdrop-blur` is gone, uppercase and wide-tracked
micro-labels are gone, no text renders below 11px, and touch pointers get 44px targets. Two
hand-rolled dialogs gained focus containment on the way. The new NSFW and video copy surfaces
follow the same rules.

## NSFW mode and uncensored providers

NSFW mode is a per-device cookie (`sunnygen.nsfw`), off by default, with a switch in Settings and
a badge in the sidebar while it is on. Turning it on asks each provider schema for its safety
fields and writes the least restrictive documented value, so a new endpoint is covered without a
code change; safe mode sends exactly what the app always sent. The mode also unlocks Wiro (Z
Image, Z Image Pro, Qwen Image Edit; uncensored variants) and a local `stable-diffusion.cpp`
sd-server, which SunnyGen talks to at `provider.local.baseUrl` but never installs.

Visibility is enforced in SQL and on the media route, not in CSS: migration 5 adds
`generations.nsfw` and `assets.nsfw` with a safe default, the repositories filter on the flag
unless the mode is on, the media route answers 404 for a hidden asset, and content dedupe matches
visibility class so a safe-mode read cannot reuse an NSFW row.

## Video copy pipeline

The Video tab has a Copy panel beside Generate | Edit: pick a source clip (600 seconds or less),
extract frames by scene change, interval or exact timestamp through ffmpeg (48 frames max), edit
any frame in the existing image editor, then let Claude Code, Codex, OMP or Pi read the stills
into a schema-checked shot list (24 shots max) or paste one. Each shot generates through the
existing start and end frame video mode, and Join concatenates the finished clips into one new
asset, stream-copying only when codec, size and frame rate match. A copy survives a reload at the
stage it reached, and frames and joined clips inherit the source's NSFW visibility.

Migration 6 adds the `video_copies` table. ffmpeg and ffprobe are now a hard requirement for this
panel; the Docker image installs them.

## Upgrade notes

- **The database backs itself up before migrating.** Migrations 5 and 6 run on first start: 5 adds
  `nsfw` to `generations` and `assets` with `DEFAULT 0` plus an index on each, and 6 creates
  `video_copies`. When an existing database has pending migrations, the app writes a consistent
  copy first with `VACUUM INTO` to `data/backups/sunnygen.db.v<from>-to-v<to>-<UTC>.db`, keeps the
  newest five of those automatic copies, and prints the path it wrote. A fresh database gets no
  copy, and if the copy fails the migration does not run, so nothing is ever migrated without a
  way back. There is still no down-migration, so keep that folder in your own backups.
- **ffmpeg is required for video copy.** `ffprobe` and `ffmpeg` must be on `PATH`
  (`apt install ffmpeg`, `brew install ffmpeg`); the Docker image now installs both. The rest of
  the app runs without them, and the panel says what to install when they are missing.
- **Agent CLIs are optional.** Shot-list analysis uses `claude`, `codex`, `omp` or `pi` if one is
  installed and logged in. Without one, paste a shot list and the rest of the pipeline works.
- **NSFW mode is per device and off by default.** It is a cookie, not a setting in the database:
  a browser that never turns it on sees safe mode, and clearing cookies returns to safe mode.
- **The theme is per device too.** It is a `localStorage` key; System follows the OS setting.
  Nothing about either mode is written to the database.
