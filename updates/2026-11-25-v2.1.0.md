# SunnyGen 2.1.0

- Version: 2.1.0
- Date: 2026-11-25
- Status: released, PRs #18 to #25

## Summary

2.1.0 is the release where the avatar stopped being a generated 4x4 sheet and became three
uploaded images, the app grew a Today screen, a shoot planner, a Studio wall and a video edit
mode, and the edit prompt learned to speak each model family's own shape. It also carries two
provider-level fixes: an input is now sent in a form the provider will actually accept, and a
Sunra job that could not fetch an input no longer poisons every retry.

Everything below links the note that shipped with its PR. Those notes hold the why, the file
list, the verification steps and the remaining limits; this page is the release-level view.

## Video edits (PR #18)

The Video tab works like the old Home wall: a video-only wall on top, a fixed Generate | Edit
composer below. Edit mode is discovered from provider schemas rather than hardcoded — an
endpoint that requires a video field and also takes a prompt plus a reference is offered as
editable — and it submits one generation per target video with the target first, filing a
multi-target submit in one batch folder. Sunra and fal both put the source video in the
schema's required video field and the references after it.

Note: [2026-11-23-video-edits.md](2026-11-23-video-edits.md)

## Edit prompts per model (PRs #19, #25)

Two changes, one direction: the prompt now says what it wants and says it in the vendor's own
shape.

PR #19 put the face swap in words. Every avatar edit prompt opens with an instruction to
replace the person in the target with the avatar, copying face, facial features, skin tone and
hair from the identity references, and the keep line stopped protecting the target's hair. It
was the missing sentence behind Nano Banana and Seedream returning the target photo nearly
unchanged.

PR #25 replaced the single shared skeleton with one template per family — nano-banana and
generic labelled sections, gpt-image numbered requirements, flux one narrative paragraph and
no negatives, seedream a Change block then a Keep fixed block, qwen terse sentences under its
800 character cap, plus new wan and grok shapes. The shared face, hair and body feature
builders and the trim tiers are reused, so a template only describes shape. The vendor
evidence is in `docs/edit-prompts.md`.

Notes: [2026-11-23-avatar-edit-face-swap.md](2026-11-23-avatar-edit-face-swap.md),
[2026-11-25-avatar-panels.md](2026-11-25-avatar-panels.md)

## Lightbox delete (PR #20)

Deleting a render in the wall lightbox left the shared action bar stuck on "Deleting…" for the
next item, because a successful delete never cleared the busy state. It now clears in a
`finally`, so the lightbox advances and the button reads Delete again. The group lightbox also
gained Delete all, which counts the deduped generation ids behind a group — queued and failed
job cards included — confirms, then deletes every one of them and the folder.

Note: [2026-11-24-lightbox-delete.md](2026-11-24-lightbox-delete.md)

## Avatar wizard and import (PR #21)

The wizard no longer generates anything. You fill the profile, copy the reference sheet prompt
and the panel prompt into your own image tool, and upload the results in Review. Paste prompt
in step 1 and the new Import avatar modal fill the profile from a pasted prompt through the
same OpenRouter call the image extraction used, and they list the traits the prompt did not
state instead of guessing. An extracted age under 18 is rejected with a clear error.

Note: [2026-11-24-avatar-wizard-uploads-toasts.md](2026-11-24-avatar-wizard-uploads-toasts.md)

## Upload naming and migration 4 (PR #21)

A user upload is now always a new asset with the original file name; when that name is taken
the new one gets a `-<uuid v4>` suffix. Internal callers — provider outputs, avatar crops, pack
and social imports — keep the content-hash dedupe, so re-uploading the same bytes is
intentional duplication rather than a silent no-op. Migration 4 adds `assets.name` and makes
the `assets_sha256` index non-unique to allow it.

Note: [2026-11-24-avatar-wizard-uploads-toasts.md](2026-11-24-avatar-wizard-uploads-toasts.md)

## Toasts (PR #21)

Every create, save, move, delete, upload, import, prepare, train and submit action in the app
now reports success and failure. Autosave, polling and reads stay silent, which is the line:
a toast belongs to something the owner did, not to something the app did on its own.

Note: [2026-11-24-avatar-wizard-uploads-toasts.md](2026-11-24-avatar-wizard-uploads-toasts.md)

## Assets page (PRs #21, #25)

The folder sidebar became `FolderChips` above the content, with New folder next to it — the old
sidebar buttons were never drop targets, so nothing was lost. PR #25 made the page list only
the owner's own files: everything a studio item owns is filtered in SQL, so paging and counts
describe the same visible list, and deleting a studio item deletes its files with it except a
file another item still points at. A generation that used a deleted file keeps its prompt and
output and shows the input as missing.

## Studio previews and wall (PR #22)

Wardrobe and scene cards open a full-size preview — the prepared image, a thumbnail strip per
view, and an Original / Prepared switch — instead of a 60 px thumbnail you could not judge.
Scenes gained the Prepare action garments already had, backed by a new scene prompt that clears
people, mannequins and clutter and returns a clean background plate, and generation references
use a scene's prepared plate when it has one. Studio renders also stopped hiding in Gallery:
the page has a wall at the top showing queued, failed and finished studio work grouped by
batch, refreshing every 3 seconds while anything is running.

Note: [2026-11-24-studio-previews-wall.md](2026-11-24-studio-previews-wall.md)

## Today, Images, Shoots (PR #23)

`/` is now Today: what is running, what finished and has not been looked at, what failed, and
how much ran this week, with Keep, Star, Delete, Move to folder and Retry in place. The image
wall moved to `/images` with its composer, and the sidebar gained Images and Shoots. The shoot
planner at `/shoots` turns one avatar, wardrobe, scenes and poses into up to eight looks in one
folder, each with an editable prompt and its ordered reference thumbnails, built by the same
helper the Studio look builder uses so the two cannot drift.

Note: [2026-11-24-home-today-shoots.md](2026-11-24-home-today-shoots.md)

## Avatar panels and three-image references (PRs #24, #25)

An avatar is now a reference sheet, a body panel and a face panel, and a model receives those
three whole images — face panel, body panel, sheet in send order, capped at the family's
documented reference count so qwen takes the two panels and loses the sheet. Each image is
labelled by the cells it holds, so the prompt can point at the face panel for the face and the
body panel's front and side profile cells for the body.

Two 2x2 panels at 4096 give each view 2048 px instead of the 1024 a 4x4 sheet gave, which was
the actual fix for blurry renders and full-body figures overflowing their cell. Nothing is cut
into tiles or recomposed into boards before a request any more: the crop editor, the adjustable
region boxes, the three composed boards and their server functions are gone, and only the purge
that sheds stale files from older avatars remains. PR #24 supplied the panel and sheet labels
and the decline handling; its hand-picked crop editor was replaced by #25's whole-image send
path.

LoRA training cuts each 2x2 panel into its four cells, so a two-panel avatar trains on eight
cells plus the sheet.

[2026-11-25-avatar-panels.md](2026-11-25-avatar-panels.md)

## Sunra fixes (PR #25)

A Sunra job that died at poll time with `input_fetch_failed` kept its upload row forever, so
every retry reused the same dead `assets.sunra.ai` URL. The poll result now reports that the
inputs are stale, and the poller asks the provider to forget them, clearing both the stored row
and the in-process upload map before the generation is marked failed.

The other half is the request itself: an 18.1 MB board was rejected by Sunra in 0.6 s because
an input over the fetch limit fails before the model runs. Stored assets stay full-quality PNG;
only the copy uploaded for one request is re-encoded, against the provider's own ceiling. Sunra
documents no number, so its ceiling is 6 MB found by trying sizes; fal keeps the shared limit.
Send-time encoding is JPEG quality 80 for opaque images and PNG or WebP only when the alpha
channel is really transparent, and a board-shaped 12.3 MB PNG comes out as a 1.95 MB JPEG at
the full 4096. A size-limit failure is now retryable, because the retry re-encodes under the
ceiling.

Note: [2026-11-25-avatar-panels.md](2026-11-25-avatar-panels.md)

## Upgrade notes

- **Migration 4 runs on first start.** It adds `assets.name`, drops the unique `assets_sha256`
  index and recreates it as a non-unique index, so an existing database at version 3 only runs
  this step. It has already run on prod (2026-11-24, `user_version` 4, 283 assets unchanged)
  and the backup taken before it is
  `~/.local/share/sunnygen-prod/data/sunnygen.db.bak-20261124-before-migration4`. Assets created
  before it have no stored name and keep the old source, size and date label until re-uploaded.
- **Old 4x4 avatars keep working.** There is no avatar migration: an avatar saved before the
  split has no face panel and sends its sheet and 4x4 panel whole on the keyword prompt, and
  its crops and boards are shed from disk on the next panel change. It stays on that legacy
  path until the three images are uploaded.
- **Backfill studio uploads.** Studio uploads used to be stored with source `studio`, which
  Assets does not list. Anything the owner uploaded through the studio dialogs or a pack import
  is an upload; only what an avatar cut for itself was internal. Dry run first, then write:
  `pnpm tsx scripts/backfill-studio-uploads.ts --db <path to sunnygen.db> --dry-run`, then the
  same without `--dry-run`. The avatar crop backfill script is gone, because crops no longer
  exist.
- **LoRA minimum is 8 images.** `LORA_MIN_IMAGES` dropped from 10 to 8 so a two-panel avatar's
  eight cells plus the sheet can be trained; an avatar saved before the split still cuts sixteen
  cells. The trainer accepts far fewer than 8, so this is policy, not a provider requirement.
- **Video Edit needs a catalog sync.** No edit mode is hand written in `models.ts`, so an
  offline or never-synced install shows an empty Edit tab until the catalog refreshes.
