# NSFW Mode Implementation Plan (revised scope)

> **Scope note:** this plan replaces the earlier draft. It was first cut down to a mode switch
> with no schema change, then the owner reinstated the visibility half: an `nsfw` flag on
> `generations` and `assets`, server-side filtering on every read path, and a media-route
> refusal in safe mode. What stays out is everything that needs a human in the loop: manual
> tag/untag, per-card badges, and the `safetyCheckers: 'on' | 'off'` behaviour change on safe
> mode.

**Status:** implemented on `henrychea/v3-nsfw`, left uncommitted for review.

**Goal:** a 😈 toggle that sweeps the app into an NSFW palette, a cookie the server can read,
least-restrictive safety fields on every provider request whose schema documents one, and
Wiro plus a local sd-server that only exist while the mode is on.

**Architecture:** the mode lives in one cookie (`sunnygen.nsfw`) read by server functions and
by a pre-paint inline script. `GenerationParams.nsfw` is stamped onto each generation at
submit time, so the stored job carries the mode it started in, and the same read writes
`generations.nsfw` / `assets.nsfw` rows so visibility never depends on the cookie at read
time. A schema-driven helper in `packages/providers/src/safety.ts` turns the param into
provider fields, and it is a no-op in safe mode. Two new provider modules sit behind
`nsfwOnly: true` model flags that `useModelChoices` filters and `submitGeneration` refuses.
Every repository read is hidden-by-default (`nsfw = 0`) and only takes `includeNsfw` from the
cookie or from a job row the server already owns.

**Tech Stack:** TypeScript, TanStack Start server functions, `@tanstack/react-start/server`
cookies, motion, `tsx --test`, `node:sqlite` untouched.

**Spec:** `docs/superpowers/specs/2026-11-25-v3-release-design.md` (section 3)

**Research:** `docs/image-providers.md` (Wiro run/poll shape, sd-server API surface)

## Global Constraints

- **Do not commit.** Leave every change in the working tree and report.
- **Migration 5, `SCHEMA_VERSION = 5`.** `generations.nsfw` and `assets.nsfw` are
  `INTEGER NOT NULL DEFAULT 0`, so every pre-existing row stays visible. The video branch
  also claims 5; whichever merges second renumbers.
- **Hidden means filtered in SQL.** No CSS, no client-side filter, no "missing" placeholder:
  a safe-mode query never returns the row, the count never includes it, and
  `/api/media/<id>` answers 404 for the bytes and the thumbnail.
- **Safe mode must not move by one byte.** Every touched provider flow is asserted in both
  modes against the same fixture; safe mode keeps today's unconditional
  `enable_safety_checker: false` on images and today's silence on video.
- **No new dependency.** Cookies come from TanStack Start, animation from `motion`, the
  probe uses `fetch`.
- **Tests never touch a network or a real provider.** Wiro and local are driven by fake
  `fetch` implementations; fal and Sunra by the existing `__fixtures__` OpenAPI documents.
- **The local provider is a client, not a supervisor.** SunnyGen never installs, builds,
  downloads models for, or restarts `sd-server`; it probes `/v1/models` and reports
  unreachable.
- Keep the file conventions: server-only modules end `.server.ts`, server functions end
  `.functions.ts`, tests sit beside the code as `*.test.ts`.

## Review Focus

1. **Hidden means refused, not hidden.** `submitGeneration` refuses an `nsfwOnly` model with
   the cookie off, before a provider is resolved. Pinned in Task 5.
2. **Picker drift.** Every picker reads `useModelChoices`; one filter there covers the home
   composer, the generate dialog, canvas nodes, the video composer, studio, and shoots.
   Pinned in Task 5.
3. **A field the schema does not document must not be sent.** The helper walks the request
   schema's properties only. Pinned in Task 2's `validateBody` assertions.
4. **Safe-mode image bodies are unchanged.** Images sent `enable_safety_checker: false`
   before this work and still do; the mode only adds fields where nothing was sent. Pinned
   in Task 2.
5. **Wiro's over-limit is not a failure.** HTTP 200 with `errors[].code == 96` becomes a
   retryable `ProviderFailure`, or the poller marks a job failed that only needed a retry.
   Pinned in Task 3.
6. **The local model is offered when the server is dead.** `localStatus()` distinguishes
   "not running" from "running without a model", the Settings card names both, and the
   picker disables the model until it is reachable. Pinned in Task 4.
7. **The NSFW palette must not depend on another theme block.** It defines its own complete
   token set; the dark-theme branch will need a one-line merge, not a dependency.

  `writeNsfwMode(enabled): void`, `loadNsfwMode()`, `setNsfwMode({ data: { enabled } })`,
  `useNsfwMode(): boolean`, `applyNsfwTheme(enabled): void`, `<NsfwToggle />`,

- [x] **Step 1: Cookie module and server functions.** `httpOnly: false` is deliberate: the
      root bootstrap reads the cookie to set `data-theme` before first paint. One year,
      `path=/`, `sameSite=lax`.
- [x] **Step 2: Token block.** `html[data-theme='nsfw']` sets canvas `#1A0F0D`, surface
      `#241513`, ink `#F6E9E4`, line `#4A2C28`, accent `#FF6B5E`, success `#5FBF84`,
      warning `#E0A64A`, error `#F0786C`. Specificity (0,1,1) beats the emitted `:root`
      (0,1,0), so no `!important`. Ink/canvas 15.83, ink/surface 14.85, accent/canvas 6.72,
      accent/surface 6.31.
- [x] **Step 3: Sweep.** One 😈 glyph crosses the viewport in 700ms over a tinted wash.
      `useReducedMotion()` swaps it for a 120ms opacity fade with no travel. Leaving the
      mode renders nothing.
- [x] **Step 4: Toggle.** `role="switch"`, `aria-checked`, visible label and state text,
      optimistic query-cache write, theme apply, then `invalidateQueries()` so every model
      list re-reads the mode. A failure restores the previous theme and reports the server
      message.
- [x] **Step 5: Reachability.** A card in Settings and a 😈 pill in the sidebar and mobile
      drawer, both linking to Settings.
- [x] **Step 6: Pre-paint.** The root route renders `try{if(document.cookie.split(';
      ').includes('sunnygen.nsfw=1'))document.documentElement.dataset.theme='nsfw'}catch(e){}`
      as a script child (not `dangerouslySetInnerHTML`).

## Dropped from the earlier draft

- `setAssetNsfwFn`, the Tag NSFW / Remove tag action, and the per-card NSFW badge: there is
  no manual tag UI in this scope.
- `GenerationParams.safetyCheckers: 'on' | 'off'` and the "turn checkers back on in safe
  mode" behaviour change. Safe mode keeps today's bodies exactly.
- Filtering by asset kind inside a generation, or a separate media root for NSFW files: the
  single row flag covers both, and the media gate reads the same row.
- The PIN open question (answered: no lock) and the global-vs-per-device question
  (answered: per device, cookie).
